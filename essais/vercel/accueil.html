Module Admin

Deux essais, deux situations

Le module s'installe sur un site qui existe déjà, ou sert à en construire un depuis une page vide. Voici les deux cas, côte à côte. Ajoutez ?admin à l'adresse pour ouvrir l'éditeur.

Site existant

Domaine de Lamartine

Le code d'un vrai site client, inchangé. Le module s'y greffe et y trouve seul 56 textes, images et liens, ainsi que les listes de cartes répétables. Aucune ligne du site n'a été modifiée : deux balises <script> ont été ajoutées, rien d'autre.

Ouvrir l'éditeur → Sans site de base

Page vierge

Un titre, un pied de page, une feuille de style minimale. Un assistant pose deux questions — une page ou plusieurs, à quoi elle sert — puis propose des mises en page et construit celle que vous choisissez.

Lancer l'assistant →

Ce qu'il faut regarder

  • Sur le site existant : l'assistant ne s'ouvre jamais, et le code reste tel quel. Survolez un titre, cliquez, écrivez. Dupliquez une carte de gîte. Publiez, puis rechargez sans ?admin.
  • Sur la page vierge : cochez plusieurs intentions pour voir les propositions changer. Une fois la page construite, tout reste modifiable, déplaçable et supprimable.
  • Sur téléphone : le panneau devient une feuille qui se replie en bas de l'écran.
Hébergement statique. Sur Vercel, la réécriture du fichier .html à la publication et le téléversement des médias ne sont pas possibles : les fichiers y sont en lecture seule après déploiement. Le contenu est servi au chargement, et l'éditeur propose un export manuel de la page figée. Sur un hébergement PHP, ces deux limites disparaissent.
