Module Admin

Installation

Vous venez d'extraire le dossier. Cette page vous emmène de là au site en ligne, éditable par votre client. Comptez 30 minutes la première fois, 5 pour les sites suivants.

0 Tout de suite

Essayez avant de configurer quoi que ce soit

Le dossier fonctionne déjà. Servez-le avec n'importe quel serveur local :

npx http-server -p 8080 .
# ou, si vous avez Python :
python3 -m http.server 8080

Puis ouvrez http://localhost:8080/index.html?admin. N'importe quelle adresse et n'importe quel mot de passe ouvrent l'éditeur : dans cet état, tout est enregistré dans votre navigateur, sans compte ni serveur.

La page index.html livrée est vierge : un assistant s'ouvre, vous pose trois questions — une page ou plusieurs, à quoi elle sert, quelle allure lui donner — et construit la page à partir de vos réponses. Vous arrivez ensuite sur le Guide : la page de haut en bas, une étape par partie, avec sous chaque champ une phrase qui dit quoi y mettre. Pour voir l'outil sur un vrai site, ouvrez plutôt demo/index.html?admin.

Vous avez déjà un site ? Rien à refaire : copiez admin/ à sa racine et ajoutez les deux lignes de l'étape 4. Votre code reste tel quel, le module s'y accroche. L'assistant ne s'ouvre que sur une page vide, et l'ambiance ne s'applique par défaut qu'aux parties que vous ajoutez : votre feuille de style n'est pas touchée.
Pourquoi un serveur local ? Un double-clic sur le fichier l'ouvre en file://, où le navigateur interdit les modules JavaScript. Toute commande ci-dessus suffit.

Quand l'outil vous convient, passez à la suite : c'est ce qui rend les modifications réelles, partagées et publiées.

1 10 minutes

Créer le projet Firebase

C'est la base de données qui garde le contenu. Le plan gratuit suffit largement pour un site vitrine.

Sur console.firebase.google.com :

  1. Ajouter un projet. Vous pouvez refuser Google Analytics.
  2. Paramètres du projet (roue dentée) ▸ Vos applications ▸ icône </> ▸ enregistrer l'application. Gardez l'objet firebaseConfig affiché : c'est l'étape 2.
  3. Authentication ▸ Commencer ▸ activer E-mail/Mot de passe.
  4. Authentication ▸ Users ▸ Ajouter un utilisateur : l'adresse et le mot de passe que vous donnerez au client. Notez l'UID affiché dans la liste.
  5. Firestore Database ▸ Créer une base ▸ mode production ▸ région eur3 ou europe-west1.
À ne pas oublier — Authentication ▸ Settings ▸ Authorized domains ▸ Add domain : ajoutez le domaine du site. Sans ça, la connexion échoue même avec le bon mot de passe. C'est l'oubli le plus fréquent.

$PROJECT_ID   = 'votre-projet';

    
Créez à côté un dossier medias/ accessible en écriture
       (chmod 755, 775 si votre hébergeur l'exige).

    

      Apache en CGI/FastCGI supprime l'en-tête
      Authorization, ce qui ferait échouer toute écriture avec une
      erreur 401. Dans le doute, ajoutez au .htaccess :
      SetEnvIf Authorization "(.*)" HTTP_AUTHORIZATION=$1
